# 案例：业务人员用 Codex 做 Python 小工具

## 用户概况（模拟）

35 岁业务人员；不会编程；常用 Codex 做表格清洗和简单 Python 小工具；中文、少术语、简短解释；偏好简单任务直接做，复杂修改先说明；删除、安装依赖、对外发送文件前先问；每次改代码后运行工具并说明验证；目标是工具可运行、结果可复核。

## 访谈如何变化

- 第 1 轮确认业务场景、不会编程、主要做表格和小工具。
- 第 2 轮只问简单/复杂任务的分界，用户选择“简单直接做，批量改动先说”。
- 第 3 轮问解释方式和语言。
- 第 4 轮问文件删除、依赖安装、外发文件；不追问部署、数据库等无关事项。
- 第 5 轮因涉及编码，问 Agent 和 Python 使用情况；不懂的环境细节留空。

## 生成结果示例

```markdown
# Agent 协作说明

## 关于我
- 我主要做业务工作，不会编程，使用 Codex 制作数据处理脚本和小工具。

## 合作方式
- 对目标明确的小改动直接处理；涉及批量修改或会改变工具流程时，先用简单语言说明方案并等我确认。
- 不要要求我理解不必要的编程术语；必须使用时先解释。

## 权限边界
### 可以直接做
- 读取和搜索当前任务相关文件，修改已确认范围内的脚本。
- 运行脚本检查结果，并报告输入、输出和验证情况。
### 做之前先问
- 删除文件、安装依赖，或把文件发送到外部。

## 验证与完成标准
- 修改脚本后运行相关脚本或现有检查；说明用了什么输入、得到什么结果。
- 不能验证时说明原因，不把“写完代码”说成“工具已可用”。

## 不确定时
- 目标或数据含义不清、可能影响原始数据时先问；不要自行覆盖原文件。
```
