# 案例：有明确工程习惯的专业开发者

## 用户概况（模拟）

专业开发者；维护后端服务；熟悉 Git、测试和架构；使用英文代码标识、中文沟通；小任务直接执行，跨模块改动先给计划；可改相关代码和运行测试；重构、依赖升级、提交、推送、部署需先确认；完成标准是相关测试通过、差异聚焦、结果说明清楚。

## 访谈如何变化

- 第 1 轮确认服务类型、语言水平、Agent 常做事项。
- 第 2 轮确认跨模块改动先计划。
- 第 3 轮确认沟通中文、技术讨论可用术语。
- 第 4 轮区分重构、依赖、Git 和部署操作。
- 第 5 轮询问确切语言、框架和测试命令；只记录用户给出的值，不假设团队约定。

## 生成结果示例

```markdown
# Agent 协作说明

## 我通常做什么
- 我维护后端服务，熟悉 Git、测试和架构设计。

## 合作方式
- 局部且目标明确的改动可直接实现。
- 跨模块或会改变架构的改动，先列出方案、影响范围和验证方式，等我确认后实施。

## 沟通偏好
- 用中文讨论；保留常见技术术语和英文代码标识。
- 汇报时说明改动、验证结果及未覆盖范围。

## 工作原则
- 只改满足当前需求所需的代码，不顺手整理无关模块。
- 优先复用项目现有结构和依赖。

## 权限边界
### 可以直接做
- 修改任务相关代码并运行已有测试。
### 做之前先问
- 大规模重构、依赖升级、Git commit、push、部署。

## 验证与完成标准
- 运行与改动相关的测试；若失败，区分本次改动与已有失败并说明证据。
- 未运行的检查明确列出，不声称验证通过。
```
